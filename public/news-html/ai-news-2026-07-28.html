月之暗面开源 Kimi K3：2.8 万亿参数 MoE 模型登顶 AI 代码工具榜单，马斯克点赞

开源大模型 Kimi K3 多模态

7 月 27 日晚，月之暗面正式开源 Kimi K3 模型权重、技术报告，并同步开源支撑训练的 MoonEP、FlashKDA、AgentEnv 三项关键 Infra 技术。Kimi K3 总参数 2.8 万亿（896 专家、激活 16），基于 KDA 混合线性注意力与 Attention Residuals 构建，原生支持视觉理解，1M token 上下文窗口，权重文件 1.4 TB，API 定价 $3/$15 per M tokens。开源几小时后登顶 AI 代码工具评测榜单 Arena，成为首个拿下该榜单第一的中国大模型，特斯拉 CEO 马斯克在评论区留下"impressive"。

值得关注的原因：Kimi K3 把"开源模型的能力上限"和"闭源前沿"的差距又拉近了一大步——过去 SWE-bench Verified 这类榜单是 Claude/GPT 的地盘，国产开源模型首次站上榜首。1M 上下文 + 原生视觉 + 2.8T 参数的组合，直接对标 Claude Fable 5 和 GPT-5.6 Sol 这类闭源旗舰。对 AI Coding 开发者来说，最实际的变化是 Anthropic Fable 5 被美国商务部一纸指令拉下线的"断供风险"再次被验证——开源权重意味着金融、医疗等强监管行业能真正"自托管"前沿级模型，不再被闭源 API 随时掐断。当然，1.4 TB 权重 + 8 台 8 卡 H100/B200 起步的硬件门槛，也把"开源≠普惠"这道鸿沟摆回了桌面。

MCP 2026-07-28 规范正式定稿：协议核心无状态化，最大规模修订重塑 Agent 工具链

AI Coding MCP 协议 基础设施

Model Context Protocol 2026-07-28 规范今日正式定稿，是自 2024 年 11 月发布以来最大规模的一次修订。核心变化：协议核心完全无状态化，移除 initialize 握手与 Mcp-Session-Id 头，任何请求可路由到任意服务器实例，可在普通轮询负载均衡器后部署；新增 Mcp-Method、Mcp-Name 两个强制 HTTP 头支持边缘路由；推出 Extensions 框架、Tasks 扩展、MCP Apps 沙箱 iframe UI；OAuth 2.1 授权对齐 W3C Trace Context 强制。Roots、Sampling、Logging 三大功能进入 12 个月弃用窗口。生态已超 1 万个公开 MCP 服务器、月 SDK 下载量破 9700 万，OpenAI/Google/Microsoft/AWS 全部内置。Beta SDK（Python v2、TypeScript v2、Go v1.7.0-pre、C# v2.0.0-preview）同步发布。

值得关注的原因：MCP 已经成为 AI Coding 工具的"事实标准神经"——Claude Code、Cursor、Copilot、OpenAI Agent SDK、Figma、Linear、Supabase 全部接入了 MCP 生态。今天这次修订不是补丁而是换骨：以前企业要部署远程 MCP 服务器，必须搞定 sticky session、共享 session store、深度包检测网关；现在可以放在普通 round-robin 负载均衡器后面。这意味着过去阻碍 MCP 在企业内网铺开最大的"运维洁癖"被根除——DevOps/SRE 团队会立刻发现，自己维护的内部工具（CMDB、监控、CI 流水线）终于可以低成本暴露给 Coding Agent。同时，新规范的 12 个月弃用窗口意味着：所有正在跑 MCP 服务器的团队，今年必须把 initialize 握手和 session 头从代码里拆掉，否则 2027 年中会集体爆雷。

Claude Code 8 天连发 8 版：2.1.210 修复 worktree 隔离数据安全漏洞，2.1.215 带来二次性能优化

AI Coding Claude Code 安全修复

7 月 14-21 日，Anthropic Claude Code 连发 8 个版本（2.1.208 至 2.1.215）。最关键的 2.1.210 修复了 worktree 隔离的子 Agent 可能在主 checkout 上执行 git 变更命令的数据安全 bug——这意味着此前并行跑 Coding Agent 的团队，存在子 Agent 误改主分支提交未审 PR 的真实风险；同时该版本强化了 Agent 工具对间接 prompt injection 的抵御能力。2.1.215 带来一项"二次方性能修复"——专门针对长会话下上下文增长导致的延迟放大问题，对每个跑长任务 Coding Agent 的团队都直接受益。

值得关注的原因：这是 2026 年 Coding Agent 工具里少见的"公开承认的、能影响生产环境的数据安全 bug"。对于习惯并行起多个子 Agent 处理不同模块的团队，2.1.210 之前的版本真的有可能让某个子 Agent 越过 worktree 边界摸到主分支——尤其当 Agent 拿到了过多工具权限时，prompt injection 会把这种边界穿透放大。强烈建议所有正在用 Claude Code 跑并行 Agent 的团队，今天就升到 2.1.215 以上。2.1.215 的二次性能修复则提醒一件事：长会话 Agent 的延迟问题不是线性增长而是平方级——选 Coding Agent 工具时，"长会话稳定性"和"上下文窗口利用率"会成为比"模型分数"更重要的评估指标。

τ0-VLA 让具身智能迈向长程任务时代：上海创智学院 × 智元机器人，长程任务成功率从 27.5% 跃升至 45%

具身智能 VLA 模型 长程任务

7 月 27 日，上海创智学院与智元机器人联合发布 τ0-VLA 模型，提出"慢思考-快执行"分层架构：上层用 Test-Time Scaling + 世界模型推演做长程规划，下层用快策略执行具体动作。模型基于 40115 小时真机数据预训练，把长程任务平均成功率从 27.5% 提升到 45.0%。这是国内学术界与机器人公司首次联手把 TTS（Test-Time Scaling）从 LLM 推理范式正式迁移到具身智能上层决策。

值得关注的原因：具身智能长期被"短任务卡壳"困住——拧螺丝、捡零件这些 5 秒内能搞定的动作成功率还行，一旦任务链条拉长到 10 步以上（比如"去仓库→识别目标→抓取→质检→码放"），成功率会从 60%+ 直线掉到 20% 上下。τ0-VLA 的真正突破不在 +17.5 个百分点的数字，而在于"分层"思路——把长程规划和短程执行解耦，让上层可以反复推演、纠错、试错，下层专心做高速精准动作。这套范式如果被产业验证，机器人从"展示 demo"走向"工厂真干活"的最大瓶颈（任务链路）会被实质性撬动。对关注 SRE/DevOps 自动化的人也有启发：Agent 系统的可靠性，本质上也是"长链路任务能不能扛"的问题，τ0-VLA 范式完全可以迁移到运维 Agent 设计里。
